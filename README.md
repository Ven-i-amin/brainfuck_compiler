# Brainfuck Compiler

Компилятор и интерпретатор языка Brainfuck с поддержкой нескольких бэкендов: интерпретация на Python, выполнение через виртуальную машину и компиляция в x86 ассемблер.

---

## Структура проекта

```
brainfuck_compiler0/
├── main.py                        # Точка входа, CLI-интерфейс
├── brainfuck.g4                   # ANTLR4-грамматика языка Brainfuck
│
├── gen/                           # Код, сгенерированный ANTLR4
│   ├── brainfuckLexer.py          # Лексер
│   ├── brainfuckParser.py         # Парсер (ANTLR4)
│   └── new_brainfuckParser.py     # Альтернативный ручной парсер
│
├── errors/                        # Обработка ошибок
│   ├── brainfuck_errors.py        # Синтаксический чекер (скобки, пустые циклы)
│   └── error_listener.py          # Кастомный слушатель ошибок ANTLR4
│
├── middleend/                     # Промежуточная обработка AST
│   ├── brainfuck_ast.py           # Узлы AST и построение дерева из parse tree
│   ├── ast_optimizer.py           # Оптимизатор AST
│   └── semantic_analyzer.py       # Семантический анализатор
│
├── brainfuck/                     # Бэкенды
│   ├── base.py                    # Абстрактный класс BrainfuckBackend
│   ├── brainfuck.py               # Интерпретатор на Python (BrainfuckInterpreter)
│   ├── x86_compiler.py            # Компилятор в x86 ассемблер
│   ├── vm_compiler.py             # Компилятор в байт-код виртуальной машины
│   ├── virtual_machine.py         # Виртуальная машина
│   └── compiler/                  # Альтернативные реализации компиляторов
│
└── vm/                            # Старая реализация виртуальной машины
    └── virtual_machine.py
```

## Основные этапы обработки кода

```
Исходный .bf файл
       │
       ▼
1. Синтаксическая проверка (SyntaxChecker)
   - Проверка парности скобок [ ]
   - Обнаружение пустых циклов []
   - Предупреждения о недопустимых символах
       │
       ▼
2. Лексический анализ (ANTLR4 Lexer)
   - Токенизация: >, <, +, -, ., , , [, ]
   - Игнорирование пробелов и комментариев
       │
       ▼
3. Синтаксический анализ (ANTLR4 Parser)
   - Построение дерева разбора по грамматике brainfuck.g4
       │
       ▼
4. Построение AST (build_ast)
   - Преобразование parse tree в узлы: ProgramNode, LoopNode, CommandNode
       │
       ▼
5. Семантический анализ (SemanticAnalyzer)
   - Проверка глубины вложенности циклов (макс. 100)
   - Обнаружение потенциально бесконечных циклов
   - Предупреждения о мёртвом коде
       │
       ▼
6. Оптимизация AST (ASTOptimizer)
   - Слияние последовательных +/- в одну инструкцию (optimized:add/sub:N)
   - Слияние последовательных >/< в одну инструкцию (optimized:right/left:N)
   - Замена паттерна [-] на команду очистки (optimized:clear)
   - Удаление пустых циклов
       │
       ▼
7. Бэкенд (на выбор)
   ├── Интерпретатор Python (BrainfuckInterpreter)
   ├── Виртуальная машина (VMCompiler → VirtualMachine)
   └── x86 Ассемблер (X86Compiler → .asm файл)
```

## Компиляция в x86 ассемблер

Команда `compile-asm` транслирует Brainfuck-программу в файл `.asm` для Linux x86-64 (синтаксис NASM).

**Что генерируется:**
- Секция `.data` с массивом памяти 30 000 байт
- Секция `.text` с точкой входа `_start`
- Регистр `r15` используется как указатель на текущую ячейку
- Ввод/вывод через системные вызовы (`sys_read` / `sys_write`)
- Каждый цикл `[...]` превращается в пару меток `loop_N_start` / `loop_N_end`

**Пример:**

```bash
python main.py compile-asm hello.bf -o hello.asm
```

После этого можно собрать и запустить (на Linux):

```bash
nasm -f elf64 hello.asm -o hello.o
ld hello.o -o hello
./hello
```

## Запуск на виртуальной машине

Команда `run-vm` компилирует Brainfuck в байт-код собственной виртуальной машины и сразу запускает его. Команда `compile-vm` сохраняет байт-код в файл `.vmbf`.

**Набор инструкций VM (OpCode):**

| Код    | Инструкция | Описание                          |
|--------|-----------|-----------------------------------|
| `0x01` | `INC`     | Увеличить текущую ячейку на 1     |
| `0x02` | `DEC`     | Уменьшить текущую ячейку на 1     |
| `0x03` | `ADD N`   | Прибавить N к текущей ячейке      |
| `0x04` | `SUB N`   | Вычесть N из текущей ячейки       |
| `0x05` | `RIGHT`   | Сдвинуть указатель вправо         |
| `0x06` | `LEFT`    | Сдвинуть указатель влево          |
| `0x07` | `MOV N`   | Сдвинуть указатель на N позиций   |
| `0x08` | `OUT`     | Вывести текущую ячейку как символ |
| `0x09` | `IN`      | Считать символ в текущую ячейку   |
| `0x0A` | `JZ N`    | Прыжок на N если ячейка равна 0   |
| `0x0B` | `JNZ N`   | Прыжок на N если ячейка не равна 0|
| `0x0C` | `CLEAR`   | Обнулить текущую ячейку           |
| `0x0D` | `SET N`   | Установить ячейку в значение N    |
| `0xFF` | `HALT`    | Завершить программу               |

**Пример:**

```bash
python main.py run-vm hello.bf
python main.py compile-vm hello.bf -o hello.vmbf
```

## Интерпретация на Python

Команда `run` выполняет Brainfuck-программу напрямую через Python-интерпретатор. Оптимизированный AST обходится рекурсивно, без промежуточного байт-кода.

```bash
python main.py run hello.bf
```

## Команды и флаги

### Команды

| Команда        | Описание                                          |
|----------------|---------------------------------------------------|
| `run`          | Интерпретировать `.bf` файл на Python             |
| `run-vm`       | Запустить `.bf` файл через виртуальную машину     |
| `compile-vm`   | Скомпилировать `.bf` файл в байт-код VM (`.vmbf`) |
| `compile-asm`  | Скомпилировать `.bf` файл в x86 ассемблер (`.asm`)|

### Позиционные аргументы

| Аргумент     | Описание                        |
|--------------|---------------------------------|
| `input_file` | Путь к исходному `.bf` файлу    |

### Флаги вывода (доступны для всех команд)

| Флаг                 | Описание                                         |
|----------------------|--------------------------------------------------|
| `-a`, `--all`        | Показать все детали (эквивалентно `-s -t -p`)    |
| `-s`, `--source`     | Вывести исходный код программы                   |
| `-t`, `--ast`        | Вывести AST до оптимизации                       |
| `-p`, `--optimization` | Вывести результаты оптимизации AST             |

### Флаг вывода файла (только для команд компиляции)

| Флаг              | Описание                                             |
|-------------------|------------------------------------------------------|
| `-o`, `--output`  | Путь к выходному файлу (по умолчанию — рядом с `.bf`)|

### Примеры

```bash
# Интерпретация
python main.py run hello.bf

# Интерпретация с выводом исходника и AST
python main.py run hello.bf -s -t

# Запуск через VM с полным выводом отладки
python main.py run-vm hello.bf --all

# Компиляция в байт-код VM
python main.py compile-vm hello.bf -o out.vmbf

# Компиляция в x86 ассемблер
python main.py compile-asm hello.bf -o out.asm

# Компиляция в ассемблер с показом оптимизаций
python main.py compile-asm hello.bf -p
```
